# Spec Delta

## Purpose

Автоматически выпускает подписанные Mozilla версии расширения в GitHub Releases, чтобы их можно было установить в Firefox/Zen навсегда и получать обновления без ручной переустановки.

## ADDED Requirements

### Requirement: Проверка каждого коммита в main
На каждый push в ветку `main` SHALL запускаться проверка: тесты, проверка типов и `web-ext lint`. Если любая из них падает, версия SHALL NOT выпускаться.

#### Scenario: Упавшие тесты
- **WHEN** в `main` попадает коммит с упавшим тестом и новой версией
- **THEN** проверка завершается ошибкой, релиз не создаётся, в AMO ничего не отправляется

### Requirement: Единый источник версии
Версия расширения SHALL задаваться только в `package.json`. Версия в манифесте собранного пакета SHALL совпадать с ней.

#### Scenario: Сборка после повышения версии
- **WHEN** в `package.json` указана версия `0.2.0` и выполнена сборка
- **THEN** манифест собранного пакета содержит версию `0.2.0`

### Requirement: Релиз только для новой версии
Релиз SHALL создаваться только если в репозитории ещё нет релиза `v<version>` для версии из `package.json`. Иначе прогон SHALL завершаться успешно после проверок, без подписи и без релиза.

#### Scenario: Коммит без изменения версии
- **WHEN** в `main` попадает коммит, а релиз `v0.1.0` для текущей версии `0.1.0` уже существует
- **THEN** проверки выполняются, прогон успешен, новый релиз не создаётся, в AMO ничего не отправляется

#### Scenario: Коммит с новой версией
- **WHEN** в `main` попадает коммит, повышающий версию до `0.2.0`, и релиза `v0.2.0` нет
- **THEN** создаётся релиз `v0.2.0`

### Requirement: Подписанный пакет в релизе
Релиз SHALL содержать пакет `hh-helper-ext-<version>.xpi`, подписанный Mozilla. Если подпись не получена, релиз SHALL NOT создаваться.

#### Scenario: Постоянная установка из релиза
- **WHEN** пользователь скачивает `.xpi` из релиза и открывает его в Firefox Release или Zen
- **THEN** расширение устанавливается как постоянное и остаётся после перезапуска браузера

#### Scenario: Подпись не получена
- **WHEN** AMO отклоняет пакет или не подписывает его за отведённое время
- **THEN** прогон завершается ошибкой, релиз не создаётся

### Requirement: Подпись без публичного листинга
Пакет SHALL подписываться так, чтобы расширение не появлялось в публичном каталоге addons.mozilla.org.

#### Scenario: Поиск в каталоге
- **WHEN** кто-то ищет расширение на addons.mozilla.org
- **THEN** его там нет

### Requirement: Автообновление установленного расширения
Установленное из релиза расширение SHALL само получать новые версии из GitHub Releases. Каждый релиз SHALL публиковать описание обновления, которое указывает на подписанный пакет этого релиза.

#### Scenario: Вышла новая версия
- **WHEN** у пользователя стоит `0.1.0` из релиза, и опубликован релиз `v0.2.0`
- **THEN** при проверке обновлений браузер находит `0.2.0`, скачивает пакет из релиза `v0.2.0` и устанавливает его без ручных действий

### Requirement: Стабильный идентификатор расширения
Идентификатор расширения SHALL быть `hh-helper-ext@alexandrlo.github.io` и SHALL NOT меняться между версиями.

#### Scenario: Обновление сохраняет установку
- **WHEN** браузер обновляет расширение с `0.1.0` до `0.2.0`
- **THEN** обновляется существующая установка, а не появляется второе расширение
