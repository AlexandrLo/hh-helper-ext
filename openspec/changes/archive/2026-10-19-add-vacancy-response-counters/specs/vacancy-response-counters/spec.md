# Spec Delta

## Purpose

Выводит на страницах поиска и вакансии hh.ru поля счётчиков откликов, которые сайт уже передал браузеру для текущей страницы, без собственных запросов и действий от имени пользователя.

## ADDED Requirements

### Requirement: Поля счётчиков на карточках поиска
Расширение SHALL выводить на каждой карточке вакансии на странице поиска hh.ru значения полей `responsesCount` и `totalResponsesCount` этой вакансии из данных выдачи, по которой нарисована карточка. Каждое значение SHALL сопровождаться исходным именем поля без переименования.

#### Scenario: Первая загрузка страницы поиска
- **WHEN** пользователь открывает `https://hh.ru/search/vacancy?...`, и начальное состояние страницы содержит вакансию с `responsesCount = 0` и `totalResponsesCount = 130`
- **THEN** у карточки этой вакансии выводится `responsesCount: 0` и `totalResponsesCount: 130`

#### Scenario: Сопоставление по идентификатору
- **WHEN** на странице есть карточки разных вакансий
- **THEN** каждая карточка показывает значения своей вакансии, определённой по идентификатору `/vacancy/<id>` в ссылке заголовка, а не по позиции в списке

#### Scenario: Одно из полей отсутствует
- **WHEN** у вакансии есть `totalResponsesCount`, но нет `responsesCount`
- **THEN** выводится только `totalResponsesCount`

### Requirement: Поля счётчиков после SPA-переходов и догрузки
Расширение SHALL выводить поля счётчиков на карточках, появившихся без перезагрузки документа: после пагинации, смены фильтров или отложенной отрисовки. Значения SHALL браться из ответа, которым сайт загрузил новую выдачу.

#### Scenario: Переход на следующую страницу выдачи
- **WHEN** пользователь переходит на вторую страницу поиска, и сайт подгружает выдачу без перезагрузки документа
- **THEN** карточки второй страницы показывают свои значения, а не значения из начального состояния первой страницы

#### Scenario: Карточка отрисована позже
- **WHEN** карточка вакансии появляется в DOM уже после того, как расширение обработало страницу
- **THEN** у неё выводятся поля, если данные для её идентификатора получены на этой странице

### Requirement: Поля счётчиков на странице вакансии
Расширение SHALL выводить на странице `https://hh.ru/vacancy/<id>` значения полей `vacancyResponsesCount` и `totalResponsesCount` из начального состояния этой страницы, каждое с исходным именем поля.

#### Scenario: Поля есть в состоянии страницы
- **WHEN** состояние страницы вакансии содержит `vacancyResponsesCount = 82` и `totalResponsesCount = 82`
- **THEN** в блоке описания вакансии выводится `vacancyResponsesCount: 82` и `totalResponsesCount: 82`

### Requirement: Только данные текущей страницы
Расширение SHALL выводить на странице только значения, полученные в пределах этой же страницы. Расширение MUST NOT сохранять счётчики между страницами или вкладками и MUST NOT выводить на одной странице данные, полученные на другой.

#### Scenario: Вакансия открыта из поиска
- **WHEN** пользователь открывает вакансию из выдачи поиска, где у неё был `responsesCount`
- **THEN** на странице вакансии выводятся только поля из состояния этой страницы, а `responsesCount` не выводится

### Requirement: Отсутствие собственных сетевых запросов и действий
Расширение SHALL получать данные только из ответов, которые сайт загружает сам. Расширение MUST NOT отправлять собственные HTTP-запросы, MUST NOT обращаться к `api.hh.ru`, MUST NOT хранить токены и учётные данные и MUST NOT выполнять действия от имени пользователя.

#### Scenario: Просмотр выдачи
- **WHEN** пользователь просматривает страницы поиска и вакансий с включённым расширением
- **THEN** в сетевом журнале нет запросов, инициированных расширением

### Requirement: Безопасная деградация
При отсутствии данных, неизвестном формате или ошибке обработки расширение SHALL ничего не выводить для затронутых карточек и страниц. Расширение MUST NOT изменять, задерживать или прерывать ответы и работу страницы сайта.

#### Scenario: Поля счётчиков исчезли
- **WHEN** состояние страницы или SPA-ответ не содержит полей счётчиков
- **THEN** на странице не появляется ни бейджей, ни заглушек, ни ошибок, а сайт работает как без расширения

#### Scenario: Ошибка разбора SPA-ответа
- **WHEN** ответ сайта не удаётся разобрать как JSON
- **THEN** страница получает ответ без изменений и в обычное время, а поля для этой выдачи не выводятся
