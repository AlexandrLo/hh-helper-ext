# hh-helper-ext

Firefox-расширение, которое показывает на hh.ru счётчики откликов на вакансии. Сайт и так присылает их браузеру, но в вебе не отображает.

Расширение только читает: не делает собственных сетевых запросов, не обращается к `api.hh.ru`, не хранит токенов и ничего не сохраняет между страницами.

## Что выводится

Поля выводятся под исходными именами hh.ru, без переименования:

| Страница | Поля |
|---|---|
| Поиск `hh.ru/search/vacancy*` — в каждой карточке, первой строкой над заголовком (и над «Сейчас смотрят N человек», если эта строка есть) | `responsesCount`, `totalResponsesCount` |
| Вакансия `hh.ru/vacancy/<id>` — после списка свойств вакансии (опыт, занятость, формат работы…), над «Сейчас эту вакансию смотрят N человек», если эта строка есть | `vacancyResponsesCount`, `totalResponsesCount` |

Если поля нет, оно не выводится. Если нет ни одного поля, бейдж не появляется.

Что известно о значениях по наблюдениям 2026-10-19 (документации нет):

- `responsesCount` на поиске бывает `0` при ненулевом `totalResponsesCount`. Похоже на отклики с момента публикации или переподнятия.
- `totalResponsesCount` на поиске почти совпадает с `vacancyResponsesCount` на странице вакансии. Поиск отстаёт на минуты.
- `totalResponsesCount` на странице вакансии — отдельное число: оно не совпадает с одноимённым полем на поиске.

## Откуда берутся данные

- **Первая загрузка страницы.** JSON из `<template id="HH-Lux-InitialState">`: на поиске `vacancySearchResult.vacancies[]`, на вакансии `vacancyView.vacancyFull.extraVacancyFields`.
- **Переходы без перезагрузки (SPA).** Ответы, которые сайт сам загружает: `/search/vacancy?...` для пагинации и `/shards/vacancy/search?...` для смены фильтров. Background читает их через `webRequest.filterResponseData`. Каждый кусок ответа сначала отдаётся странице без изменений, разбирается только копия.

Это внутренние, недокументированные поля фронтенда hh.ru. Сайт может переименовать или убрать их в любой момент. Тогда расширение просто перестанет что-либо показывать, не ломая страницу.

## Сборка

Нужен Node.js 25+: тесты запускаются на `.ts` без отдельной компиляции.

```sh
npm install
npm test           # разбор данных на реальных урезанных образцах
npm run typecheck
npm run build      # -> dist/
npm run lint       # сборка + web-ext lint
```

## Установка

Вариант 1, временная установка одним файлом (подходит и для браузеров в песочнице Flatpak/Snap):

1. `npm run package`. Получится `web-ext-artifacts/hh-helper-ext.xpi`.
2. Открыть `about:debugging#/runtime/this-firefox`.
3. «Загрузить временное дополнение…» → выбрать `web-ext-artifacts/hh-helper-ext.xpi`.

Почему одним файлом: браузер из Flatpak видит только файл, выбранный в диалоге. Если выбрать `dist/manifest.json`, соседние `background.js` и `content.js` ему недоступны, и расширение не работает (`Loading failed for the <script> … background.js`).

Временное дополнение удаляется при перезапуске браузера. После изменений повторите `npm run package` и загрузите `.xpi` заново.

Без песочницы можно выбрать и `dist/manifest.json` после `npm run build`.

Вариант 2, отдельный профиль:

```sh
npm start          # сборка + web-ext run на странице поиска
```

## Проверено

Headless Firefox 158 (через `web-ext run` и WebDriver BiDi), без входа в аккаунт:

- Поиск, первая загрузка: бейджи у 50 из 50 карточек, 0 расхождений со значениями из состояния страницы, дубликатов нет.
- Пагинация (SPA, документ не перезагружается): бейджи у 50 из 50 новых карточек.
- Смена фильтра «Опыт» (SPA через `/shards/vacancy/search`): бейджи у 50 из 50, 0 расхождений с ответом сайта.
- Страница вакансии: бейдж `vacancyResponsesCount: … · totalResponsesCount: …` совпадает с состоянием страницы, других полей нет.
- Поля переименованы во временной сборке (имитация изменения сайта): бейджей нет. Пагинация, фильтры и страница вакансии работают; ошибки страницы — только от рекламных скриптов.
- В исходниках и сборке нет `fetch`, `XMLHttpRequest`, `sendBeacon`, `WebSocket`, `storage.*` и `api.hh.ru`. У расширения нет разрешения `storage`.

Zen 1.23.3b (движок Firefox 157, установка через Flatpak), с входом в аккаунт hh.ru, расширение установлено из `.xpi`: бейджи отображаются на поиске и на странице вакансии (проверено пользователем 2026-10-19).
